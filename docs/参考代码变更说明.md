## 3. 核心接口与实现要点

### 3.1 币种元数据与格式化

```ts
export type CurrencyCode = 'CNY' | 'USD' | 'JPY'

export const CURRENCIES: Record<CurrencyCode, CurrencyMeta> = {
  CNY: { code: 'CNY', symbol: '¥', numeric: '156', fractionDigits: 2, labelKey: 'currency.CNY' },
  USD: { code: 'USD', symbol: '$', numeric: '840', fractionDigits: 2, labelKey: 'currency.USD' },
  JPY: { code: 'JPY', symbol: '¥', numeric: '392', fractionDigits: 0, labelKey: 'currency.JPY' },
}

export function formatMoney(value: number, currency: CurrencyCode): string
// ¥1,234.00 / $88.50 / ¥68（JPY 无小数）
```

要点：
- 取整发生在**币种最小单位**，`roundMoney(value, currency)` 用 `10 ** fractionDigits` 作为因子，避免 JPY 被错误保留 2 位小数。
- `formatMoney` 负责千分位，页面不再手拼符号或 `toFixed`。
- `describeMoney(value, currency)` 返回 `JPY ¥68` 形式的辅助文本，用于 `aria-label` 消除 CNY/JPY 同为 `¥` 的歧义。

### 3.2 加总与优惠

```ts
export const sumLineTotals = <T extends { price: number; quantity: number }>(items: T[], currency: CurrencyCode) =>
  roundMoney(items.reduce((sum, item) => sum + roundMoney(item.price * item.quantity, currency), 0), currency)

export const DISCOUNT_THRESHOLD = 100
export const DISCOUNT_AMOUNT = 30
export const calcDiscount = (subtotal: number, currency: CurrencyCode) =>
  subtotal < DISCOUNT_THRESHOLD ? 0 : Math.min(DISCOUNT_AMOUNT, roundMoney(subtotal, currency))
```

- **必须显式传币种**：所有调用点都传入 `currency`，从类型层面阻止漏传导致的串币。
- 优惠门槛/面额为门店本币金额，不做汇率折算。

### 3.3 门店 → 桌台 → 币种

```ts
export const stores: Store[] = [
  { id: 'xingheli', nameKey: 'store.xingheli', currency: 'CNY' },
  { id: 'harbor',   nameKey: 'store.harbor',   currency: 'USD' },
  { id: 'shinjuku', nameKey: 'store.shinjuku', currency: 'JPY' },
]
export const tableStore: Record<string, string> = { A08: 'xingheli', B12: 'harbor', C06: 'harbor', D03: 'shinjuku' }
```

- 币种是门店属性，桌台映射只是演示数据；未知桌台回落首家门店（CNY）。
- `BIND_TABLE` 时写入 `state.currency`，页面全部从 `state.currency` 读取，顾客无入口修改。

### 3.4 预览 / 验收直达

- `?currency=USD|JPY` + `#/menu`、`#/checkout` 等可直达目标视图，并预置一桌订单/购物车数据（Mock），无需后端或基础数据。
- 非法的 `?currency=`（例如 `HKD`）被忽略，按普通深链接处理。
- 未绑定桌台的深链接默认 A08（CNY）。

## 4. 关键行为对照（修改前 → 修改后）

| 场景 | 修改前 | 修改后 |
|---|---|---|
| 菜单价格 | `money(68)` → `¥68.00` | `formatMoney(68, 'USD')` → `$68.00`；JPY → `¥68` |
| 购物车小计 | `items.reduce(...)` | `sumLineTotals(items, currency)` |
| 半份价格 | `Math.round(price * 0.58)`（按 ¥ 整数） | `roundMoney(price * 0.58, currency)`（JPY 取整、USD/CNY 2 位） |
| 优惠 | `subtotal >= 100 ? 30 : 0` | `calcDiscount(subtotal, currency)`，本币门槛与面额 |
| 币种来源 | 无 | 门店/桌台决定，`state.currency` 只读 |
| 币种切换 | 无 | 仍无；顶栏说明「门店本币定价，不做汇率换算」 |

## 6. 后续开发节点注意事项

1. 新增金额展示必须使用 `formatMoney(value, currency)`，禁止直接拼接符号或 `toFixed`。
2. 新增加总/优惠逻辑必须传币种，禁止跨币种相加。
3. 若扩展货币（如 HKD），需同时更新 `CurrencyCode`、`CURRENCIES`、`fractionDigits`、i18n 与 E2E 矩阵，并重新评估优惠门槛口径。
4. 真实门店定价接入后，`stores`/`tableStore` 应替换为后端下发，但保持 `state.currency` 契约不变。
5. JPY 无小数，任何按比例折算（半份、折扣）都必须走 `roundMoney(value, 'JPY')`。
