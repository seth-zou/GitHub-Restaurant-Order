主题体验增强
白天 / 夜间 / 跟随系统

在已交付的白天/夜间双主题基础上，升级为三态主题体验：用户可长期选择「跟随系统」，界面随设备偏好实时变化，主题入口清晰表达当前偏好，并用自动化守卫保证全站暗色一致性。

优先级 P2 需求类型：UX / 可访问性 / 前端状态 打标结论：A 类 单仓闭环 基线 main @ 58ee88a

Review Summary

  • 本次需求：将双主题升级为「跟随系统 / 白天 / 夜间」三态主题体验，补齐实时联动、可读入口与暗色一致性守卫。
  • 变更面：Functional Requirements、UX Design、Data & Storage、NFR / DFX、Test Cases、Traceability、需求打标。
  • 不涉及：API Design、Metrics、后端服务、数据迁移。
  • 判断依据：需求澄清文档 v2；仓库 AGENTS.md、useThemeMode、ThemeToggle、index.css、index.html、theme-mode E2E；空间任务 task-yezk3b78xsyl5rhlestd 已交付基线。
  • 差异判断：不涉及产品形态 / 站点 / 环境 / 版本差异；单仓 React SPA，hash 路由，GitHub Pages 子路径部署。
  • Review 重点：三态优先级、系统联动边界、弹层可访问性、暗色对比度与根背景、旧值兼容、存储失败降级、业务回归。

1. Context

本 PRD 基于「需求澄清文档 v2」，目标仓库 seth-zou/GitHub-Restaurant-Order，基线 main @ 58ee88a，工作分支 feat/93300da1-55b2。

  • TD-1 关闭：继续使用 darkMode: 'class' + src/index.css 集中暗色映射，不引入 CSS 变量 / token 体系；用守卫命令约束新增颜色类。
  • TD-2 关闭：系统偏好监听兼容 addEventListener 与旧版 addListener，能力不可用回退白天。
  • 原双主题能力已在基线交付；本文只描述本次增强的行为契约、验收与打标。

2. Goals / Non-Goals

Goals

  • 「跟随系统」成为可长期保持的用户状态，并实时联动。
  • 入口与弹层清晰表达当前偏好与当前生效模式。
  • 用自动化守卫防止暗色映射随迭代劣化。

Non-Goals

  • 不做自定义主题色、品牌主题包、主题市场。
  • 不做定时 / 日出日落切换、按页面独立主题。
  • 不做账号级或跨设备同步、埋点。
  • 不改造老人模式；不修复顶栏 375px 既有溢出。

3. 功能需求

REQ-101

三态主题偏好与默认策略

P0

偏好取值为 system / light / dark，默认 system。无有效保存值时按系统偏好解析；系统偏好不可用时解析为 light。用户显式选择优先。

Acceptance (EARS)
  • 本地无有效值且系统 dark → 以 system 渲染夜间。
  • 本地无有效值且系统 light / 未声明 / 能力不可用 → 渲染白天。
  • 保存值为 light / dark → 优先该值并忽略系统偏好。
  • 保存值为 system → 按系统偏好解析。
  • 非法值 → 视为未保存并按默认策略解析。
  • 用户显式选择 → 立即应用并写入本机存储。
REQ-102

跟随系统实时联动

P0

偏好为 system 时监听 prefers-color-scheme 并即时更新；偏好为 light / dark 时不响应系统变化。

Acceptance (EARS)
  • system 下系统变化 → 立即更新生效模式、html.dark、data-theme-mode 与 theme-color。
  • 显式偏好下系统变化 → 保持当前生效模式。
  • 切回 system → 立即按系统偏好渲染并继续监听。
  • 监听能力不可用 → 保持白天且不抛错。
REQ-103

主题入口与外观设置弹层

P0

主流程顶栏、首页、欢迎页提供 44px 主题入口；图标表示当前偏好，可访问名称说明当前偏好与打开设置。点击打开「外观模式」弹层，提供三个互斥选项、当前设备偏好与当前生效模式说明。

Acceptance (EARS)
  • 五个视图（home / welcome / menu / order / checkout）入口可见、可聚焦、可触发。
  • 弹层展示三个互斥选项并标记当前偏好。
  • 选择后立即应用并关闭弹层。
  • 「跟随系统」选项显示当前设备实际偏好。
  • Esc / 关闭 → 关闭弹层并将焦点返回入口。
  • 中英文入口名称、选项与说明同步。
  • 选中态由图标、勾选标记和文字共同表达。
  • 切换不产生布局跳动或路由变化。
REQ-104

全站暗色一致性与可读性

P0

夜间模式覆盖页面底色、卡片、弹层、Toast、底部导航、主 CTA、表单、状态徽章和图片遮罩。html 与 body 均使用暗色基线；文本与关键状态保持 WCAG AA；焦点可见；状态不以颜色为唯一载体。

Acceptance (EARS)
  • html、body、页面容器均使用暗色背景，短页面与滚动越界不露浅色底。
  • 正文、价格、订单状态、售罄与风险提示、按钮文案 ≥ 4.5:1。
  • 键盘焦点环可辨识。
  • 图片、遮罩、状态标识不遮挡关键信息，不以颜色作为唯一识别方式。
  • 出现未映射浅色块、低对比文本或不可读控件视为不满足。
REQ-105

主题覆盖守卫与维护契约

P1

npm run theme:check 扫描 src/**/*.{ts,tsx} 中的自定义色板颜色类，校验存在 .dark 映射或属于「深色底安全清单」；遗漏时非零退出并输出类名与文件。

Acceptance (EARS)
  • 全部颜色类均有映射或安全归类 → 退出码 0。
  • 存在未映射且未归类的类 → 非零退出并列出类名与文件。
  • 深色底安全类需在脚本清单显式登记并说明原因。
  • 校验不引入运行时网络请求或第三方依赖。
REQ-106

降级、兼容与隐私

P1

本机存储不可用时降级为当前页面会话内存态；系统偏好能力不可用时回退白天；历史 light / dark 值继续有效；偏好不上报、不同步。

Acceptance (EARS)
  • localStorage 读取或写入不可用 → 会话内继续支持三态切换，无用户可见错误。
  • 写入失败后继续切换 → 优先本次会话选择，而不是旧存储值。
  • matchMedia 不可用 → 白天模式，手动切换可用。
  • 不向网络或后端发送主题偏好，不新增 Cookie / 埋点。
  • React 挂载前完成主题判定，避免可见闪烁。
REQ-107

业务流程与路由不受影响

P0

主题切换只改变视觉呈现，不改变路由、桌台、购物车、订单、服务请求与结账状态，不触发网络请求或数据重置。

Acceptance (EARS)
  • 切换后 URL、桌台与购物车内容不变。
  • 订单/结账流程切换不重置订单、支付方式或履约进度。
  • 切换不产生控制台错误。
  • 浅色与夜间分别完成主流程，业务结果一致。

关键场景（Gherkin 摘要）

Scenario: 跟随系统时自动切换
  Given 用户偏好为 system 且系统为 light
  When 系统切换为 dark
  Then 界面立即切换为夜间模式
  And 用户偏好仍为 system

Scenario: 打开外观模式并切换
  Given 用户处于点餐页且偏好为 system
  When 用户打开主题入口并选择「夜间」
  Then 界面立即渲染夜间模式
  And 弹层关闭且焦点回到主题入口

Scenario: 存储不可用
  Given 浏览器禁止 localStorage
  When 用户切换到夜间模式并继续点餐
  Then 当前会话保持夜间模式
  And 点餐与提交订单可继续完成

4. UX Design

入口位置

外观设置弹层移动端贴底 / 桌面居中选择后立即生效关闭后焦点回到入口

弹层结构

  1. 标题：外观模式。
  2. 说明：选择界面亮度；“跟随系统”会随设备设置自动切换。
  3. 三个互斥选项：跟随系统（含「当前设备」说明）、白天、夜间。
  4. 选中态：辣红边框 + 浅辣红底 + 勾选图标 + 文字加粗。
  5. 底部状态：当前界面：白天 / 夜间。

5. Data & Storage

对象契约校验 / 优先级兼容性
localStorage.theme-modesystem / light / dark显式选择 > 系统偏好 > 白天；非法值按未保存历史 light / dark 继续有效
html.dark夜间模式唯一全局类随生效模式同步复用 Tailwind darkMode: 'class'
data-theme-modelight / dark实际生效模式既有测试与排查入口
data-theme-preferencesystem / light / dark用户偏好本次新增
meta[name="theme-color"]light #fbf5ea / dark #12100d随生效模式同步浏览器地址栏配色

迁移与回滚

  • 不迁移历史数据；旧值直接可用。
  • 回滚时遗留的 theme-mode=system 会被旧版本视为非法值，回退系统偏好或白天，不阻塞业务。
  • 主题偏好仅存在于本设备浏览器，不构成服务端契约。

类别要求验收方法

性能主题判定在首屏渲染前完成；切换仅触发颜色过渡；不新增网络请求构建产物核对 + 人工观察
可维护性单一暗色映射源 + npm run theme:check 守卫；不新增未登记颜色守卫命令通过
安全与隐私不采集、不上报、不同步主题偏好；不新增 Cookie / 埋点 / 第三方代码检索
发布与回滚随前端版本发布，无数据库迁移；回滚仅移除入口与状态逻辑构建 + 回滚说明
