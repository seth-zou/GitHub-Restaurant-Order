# 需求澄清：支持人民币、美元、日元的展示和计算

> 输入来源：用户原始需求「支持人民币（CNY）、美元（USD）、日元（JPY）三种货币的展示和计算能力，包括多币种金额展示、汇率换算与金额计算。」
> 确认结果：需求确认卡片（2026-11-18）三项业务口径已由需求负责人确认。
> 证据：`repos/seth-zou_GitHub-Restaurant-Order`（基线 `main` @ `58ee88a`，工作分支 `feat/6f2b2507-ztnc`）。

## 1. 需求与目标

### 一句话需求
在沸点火锅点单概念演示 SPA 中，把当前硬编码人民币的金额展示与加总升级为支持人民币（CNY）、美元（USD）、日元（JPY）三种货币，使就餐顾客在对应货币门店中看到、加总并结账时金额始终使用同一本币，同时**不做汇率换算、不允许整桌混币**。

### 背景
- 现状（代码证据）：`src/lib/utils.ts` 的 `money()` 硬编码 `¥` 与 2 位小数；`src/data/menu.ts` 菜品只有一个数值价格；`src/components/{MenuView,CartPanel,OrderView,CheckoutView}.tsx`、`src/App.tsx` 均直接调用 `money()`。
- 演示目标是「从桌台绑定到结账」的完整门店流程，但门店只有一家、只有人民币口径，无法演示海外门店/多币种定价场景。
- 仓库无后端定价或汇率服务（`server/` 仅健康检查），所有数据为前端内存态。

### 目标与成功标准
- 目标 1：菜单、购物车、订单、结账、会员权益等所有出现金额的位置，都能按当前门店币种正确展示。
- 目标 2：同一张桌台的金额加总、优惠与应付在单一币种下自洽且可验算。
- 成功标准 1：绑定人民币 / 美元 / 日元门店桌台后，全流程金额符号与精度与门店币种一致，且同一账单不出现第二种币种。
- 成功标准 2：顾客在任意页面都找不到「切换币种」或「汇率换算」入口，页面明确说明按门店本币定价。

## 2. 范围与业务规则

### 范围
- 做什么：
  - 新增币种能力层（币种元数据、格式化、按币种精度取整、行项目加总、优惠与应付计算）。
  - 店铺/桌台到币种的演示映射，覆盖 CNY、USD、JPY 三种货币。
  - 菜单卡片与规格弹窗、购物车（含移动端弹层）、订单页、结账页、顶栏币种徽标、会员菜品券文案的多币种改造。
  - 中英文文案同步、`?currency=USD|JPY` 预览直达、E2E 验收用例。
- 不做什么：
  - 不做汇率换算、不接实时汇率或任何外部价格/汇率服务。
  - 不允许顾客自行切换币种，不做整桌多币种混排或双列参考币种展示。
  - 不支持 CNY/USD/JPY 之外的货币（原分支中的港币 HKD 已收敛移除）。
  - 不改动后端、订单持久化、支付通道与 `server/` 健康检查。
  - 不新增真实多门店数据源、会员体系或价格管理后台。

### 核心业务规则
- MC-R1：币种是门店属性，由桌台所属门店决定；绑定桌台后写入整桌币种，全链路只读。
- MC-R2：整桌只允许一种币种；金额加总、优惠和应付必须使用同一种币种，禁止跨币种直接相加。
- MC-R3：门店以本币定价，展示与计算均为该币种原值，不进行任何汇率换算。
- MC-R4：金额精度按 ISO 4217 最小货币单位：CNY、USD 保留 2 位小数；JPY 保留 0 位小数（整数）。
- MC-R5：金额展示格式为「货币符号 + 千分位 + 币种精度」（如 `¥1,234.00`、`$88.50`、`¥68`）；CNY 与 JPY 符号同为 `¥`，关键位置需以 ISO 代码（CNY/JPY）或可访问文本消除歧义。
- MC-R6：门店满额减活动（门槛 100、面额 30）为门店本币金额，按本币小计判断与扣减；优惠不超过小计。
- MC-R7：切换中英文只影响文案，不改变币种与金额格式。
- MC-R8：演示桌台映射：`A08 → 星河里店(CNY)`、`B12 → 海港城店(USD)`、`C06 → 海港城店(USD)`、`D03 → 新宿店(JPY)`；未知桌台回落人民币门店。

### 边界与异常
- 未知/未绑定桌台：使用默认人民币门店，不报错。
- 非法的 `?currency=` 预览参数：忽略该参数，按普通深链接逻辑进入 A08（CNY）。
- 金额出现浮点尾数：统一按币种最小单位四舍五入后再展示与加总。
- 保持不变：主流程 `home → welcome → menu → order → checkout`、hash 路由、多人协同、售罄、服务呼叫、演示控制台、夜间模式与老人模式行为。

## 3. 用户与场景（概要）

- 目标用户：在沸点门店就餐、通过扫码点单的顾客；演示/验收人员。
- 使用场景：顾客绑定桌台后浏览菜单、加入购物车、提交订单、查看订单与结账；不同门店桌台对应不同本币。
- 关键路径概要：绑定桌台（确定币种）→ 浏览菜单并加入购物车（本币展示）→ 提交订单 → 结账（本币小计、优惠与应付）。

## 4. 未决项

### 待确认（业务契约）
- 无。三项关键口径已确认：
  1. 对已有同名货币分支：**复用该分支并收敛到 CNY/USD/JPY**。
  2. 三种货币如何出现在点单流程：**门店/桌台决定整桌币种**。
  3. 是否需要汇率换算：**不做换算，按门店原币定价直接展示与加总**。
