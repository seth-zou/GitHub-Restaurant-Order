# 需求澄清：主题体验增强（白天 / 夜间 / 跟随系统）

> 版本：v2（2026-11-16）
> 变更来源：原需求「支持白天和夜间模式」经重复性评估后，需求负责人确认**变更为「主题体验增强」**，优先级 **P2**。
> 本文只记录需求决策信息；详细交互、状态、文案与验收见 `docs/PRD 文档.md`。

## 1. 需求与目标

### 一句话需求

在沸点火锅点单 SPA 已交付的白天/夜间双主题基础上，升级为「白天 / 夜间 / 跟随系统」三态主题体验，使就餐用户与门店演示者能够按环境与设备偏好稳定选择界面亮度，同时不改变任何点餐业务流程。

### 背景

- 2026-11-15 空间内「支持夜间模式」任务已执行成功，双主题、本机持久化、系统偏好默认与 E2E 已合入 `main`（PR #1）。
- 现状存在三个用户可感知缺口：手动切换后无法再回到「跟随系统」；主题入口只有图标，当前模式缺少文字说明；暗色下 `html` 根背景仍为浅色，极端滚动场景会露出浅色底。
- 原需求与已交付能力高度重复，需求负责人选择将其升级为体验增强，避免重复建设。

### 目标与成功标准

- 目标：让「跟随系统」成为可选择的长期状态，并让界面在系统偏好变化时自动跟随。
- 目标：让用户能一眼看清当前主题偏好，并在一个入口内完成三态选择。
- 目标：把暗色一致性从人工巡检升级为可自动执行的覆盖校验。
- 成功标准：三态选择、持久化、系统联动、异常降级均可被自动化用例稳定验证；主题覆盖校验命令通过。
- 成功标准：点餐、订单、结账、服务与路由行为在任意主题下不发生改变。

## 2. 范围与业务规则

### 范围

- 做什么：
  - 主题偏好扩展为 `system` / `light` / `dark` 三态，默认 `system`。
  - 选择「跟随系统」时，系统偏好运行时变化即时联动；显式选择白天/夜间时不再联动。
  - 主题入口保留在主流程顶栏、首页与欢迎页，打开「外观模式」弹层完成选择。
  - 修复暗色下根元素背景与根文字色、焦点环、未覆盖的 hover / focus 颜色类。
  - 新增主题覆盖守卫命令，阻止新增颜色类遗漏夜间映射。
  - 同步更新 E2E、仓库说明与产品文档。
- 不做什么：
  - 不做自定义主题色、品牌主题包、主题市场。
  - 不做按时间自动切换（日出日落）、按页面独立主题。
  - 不做账号级同步、跨设备同步、服务端存储。
  - 不新增埋点、Cookie 或第三方服务。
  - 不改造老人模式机制，不与老人模式合并为同一开关。
  - 不在本次修复顶栏在 375px 下的既有横向溢出（记录为已知问题，另立需求）。

### 核心业务规则

- 偏好取值只有 `system`、`light`、`dark`；默认 `system`。
- 用户显式选择优先于系统偏好，并在本设备持久化；选择「跟随系统」后重新以系统偏好为准。
- `system` 状态下监听 `prefers-color-scheme` 变化并即时应用；`light` / `dark` 状态下不响应系统变化。
- 系统偏好不可读取或能力不可用时，按白天模式渲染，不阻断业务。
- 本机存储不可用时，降级为当前页面会话内存态，不报错、不阻塞点餐。
- 历史保存值 `light` / `dark` 继续有效；非法值按「未保存」处理，走默认策略。
- 主题切换只影响视觉呈现，不改变路由、桌台、购物车、订单、服务与支付状态，不发起网络请求。
- 主题入口必须在主界面可见、可聚焦、可操作；选中项不能只靠颜色区分。
- 新增主题相关文案必须中英文同步。

### 边界与异常

- 同一页面存在多个主题入口时，状态必须一致。
- 首屏必须在 React 挂载前完成主题判定，避免可见闪烁。
- 弹层打开、关闭、Esc、焦点回归必须可用；主题切换不造成布局跳动。
- 系统偏好运行时变化只影响 `system` 偏好，不影响用户显式选择。

## 3. 用户与场景（概要）

- 目标用户：到店就餐用户；门店演示与运营人员。
- 使用场景：明亮大厅、暗光包间、夜间使用；设备已开启深色模式并希望全站自动跟随。
- 关键路径概要：
  1. 用户进入点单页，界面按上次偏好或系统偏好渲染。
  2. 用户打开「外观模式」，选择跟随系统 / 白天 / 夜间，界面立即生效。
  3. 后续访问沿用该偏好；选择跟随系统时，系统切换深浅色后界面自动跟随。

## 4. 未决项

### 待确认（业务契约）

- 无。需求负责人已确认「升级为主题体验增强」与优先级 P2。

### 技术待设计

- TD-1：主题机制是否演进为 CSS 变量 / 语义 token 体系。
  - 证据：仓库 `AGENTS.md` 明确「颜色类名直接硬编码，不用 CSS 变量或语义 token 层」，现有实现在 `src/index.css` 用 `.dark` 集中映射。
  - 候选方向：A. 保持集中映射 + 覆盖守卫（本次采用）；B. 全站渐进 token 化。
  - 影响：B 需要改动全部页面类名，回归面大、风险高，且与仓库现有约定冲突。
  - 建议处理节点：后续独立技术需求；本次仅在 PRD 中固化「集中映射 + 守卫」的维护契约。
- TD-2：系统偏好监听的旧浏览器兼容。
  - 证据：`MediaQueryList.addEventListener` 在旧 Safari 使用 `addListener`；参考实现已做双 API 兜底。
  - 影响：仅影响极旧浏览器；无业务口径差异。
  - 建议处理节点：研发实现时保持兜底即可。
